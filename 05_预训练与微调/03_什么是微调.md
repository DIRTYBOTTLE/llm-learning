# 5.3 什么是微调

> 微调就像专业培训：在已有知识的基础上，学习特定领域的技能。

## 从你已经知道的开始

在上一节，你学了：
- 预训练让模型"懂很多"
- 但基座模型不会"对话"

**这一节，我们来看看怎么让模型学会"对话"！**

## 二、微调的定义

### 什么是微调？

**微调 = 在预训练模型的基础上，用特定任务的数据继续训练**

```
微调的过程：

输入：预训练好的基座模型 + 特定任务的数据
  - 基座模型：已经懂很多知识
  - 任务数据：比如对话数据、问答数据

训练：让模型学习特定任务

输出：一个"会对话"的助手模型
```

### 微调的目标

**目标：让模型学会特定任务，同时保留预训练学到的知识**

```
微调要平衡：

1. 学会新任务
   - 比如：学会对话、学会回答问题
   
2. 保留旧知识
   - 不能忘记预训练学到的知识
   - 比如：语法、语义、世界知识
```

## 三、微调的数据

### 数据规模

```
预训练 vs 微调的数据规模：

预训练：
  - 数据量：万亿 token
  - 来源：书籍、网页、代码
  - 成本：很高

微调：
  - 数据量：几万到几百万条
  - 来源：人工构造的对话数据
  - 成本：相对较低
```

### 微调数据的例子

```
对话数据：
  用户：你好，你是谁？
  助手：你好！我是一个AI助手，很高兴为你服务。

问答数据：
  问题：中国的首都是哪里？
  答案：中国的首都是北京。

指令数据：
  指令：请帮我写一首关于春天的诗。
  输出：春风拂面暖阳照，万物复苏花开了...
```

## 四、微调的过程

### 用具体例子理解

```
基座模型已经学会：
  - "北京"是"中国"的首都
  - "天气"后面可能接"好"或"坏"

微调让它学会：
  - 用户问问题，要回答
  - 不要继续写文章，要回答问题

训练数据：
  用户："北京是中国的首都吗？"
  助手："是的，北京是中国的首都。"

模型学习：
  - 看到"是...吗？"要回答"是"或"不是"
  - 不要继续写"北京是中国的首都，位于..."
```

### 微调的代码示例

```python
def prepare_finetune_data(conversations):
    """
    准备微调数据
    """
    input_ids = []
    target_ids = []
    
    for conv in conversations:
        # 用户的问题
        user_text = conv["user"]
        # 助手的回答
        assistant_text = conv["assistant"]
        
        # 构造输入："用户：{问题} 助手："
        input_text = f"用户：{user_text} 助手："
        # 构造目标："{回答}"
        target_text = assistant_text
        
        input_ids.append(tokenize(input_text))
        target_ids.append(tokenize(target_text))
    
    return input_ids, target_ids

# 例子
conversations = [
    {"user": "你好", "assistant": "你好！有什么可以帮你的吗？"},
    {"user": "1+1等于几？", "assistant": "1+1等于2。"},
]
```

## 五、基座模型 vs 助手模型

### 对比同一个问题的回答

```
问题："请介绍一下北京。"

基座模型（没有微调）：
  "请介绍一下北京。上海是中国的经济中心..."
  或者：
  "请介绍一下北京。北京是中国的首都，位于华北平原，
   面积16410平方公里，人口2154万..."
  （在续写，可能跑题，可能很长）

助手模型（经过微调）：
  "北京是中国的首都，也是中国的政治、文化中心。
   它位于华北平原，有着悠久的历史和丰富的文化遗产。"
  （在回答问题，简洁、准确）
```

### 对比对话能力

```
对话：

用户："你好"
基座模型："你好世界！Hello World!"（在续写）
助手模型："你好！有什么可以帮你的吗？"（在对话）

用户："1+1等于几？"
基座模型："1+1等于几？这是一个数学问题..."（在续写）
助手模型："1+1等于2。"（在回答）
```

## 六、为什么需要微调？

### 基座模型的问题

```
1. 不会对话
   基座模型只是在"续写文本"
   不知道怎么"回答问题"
   
2. 可能胡说八道
   基座模型会续写出看起来合理但错误的内容
   比如："太阳从西方升起"
   
3. 不知道边界
   基座模型不知道什么该说，什么不该说
   可能会输出有害内容
   
4. 不遵循指令
   基座模型不会按照指令做事
   比如："请用三句话总结"，它可能写很多
```

### 微调解决这些问题

```
微调让模型学会：

1. 学会对话
   用户问问题 → 回答问题
   
2. 减少胡说八道
   学会说"我不知道"而不是编造答案
   
3. 知道边界
   学会拒绝有害请求
   
4. 遵循指令
   学会按照指令做事
```

## 七、总结

### 微调的关键点

| 概念 | 说明 |
|------|------|
| 定义 | 在预训练模型基础上，用特定任务数据继续训练 |
| 数据 | 特定任务的数据（对话、问答等） |
| 目标 | 学会特定任务，同时保留预训练知识 |
| 结果 | 助手模型（会对话、会回答问题） |

### 微调的比喻

```
微调 = 专业培训
  - 在已有知识的基础上
  - 学习特定领域的技能
  - 成为专业人才

助手模型 = 专业人才
  - 保留了广泛的知识
  - 掌握了专业技能
  - 可以胜任工作
```
