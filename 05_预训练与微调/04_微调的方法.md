### 步骤4：训练循环

```python
def train(model, train_dataloader, optimizer, num_epochs):
    """训练循环"""
    
    model.train()
    
    for epoch in range(num_epochs):
        total_loss = 0
        
        for batch in train_dataloader:
            # 1. 前向传播
            outputs = model(
                input_ids=batch["input_ids"],
                attention_mask=batch["attention_mask"],
                labels=batch["labels"]
            )
            loss = outputs.loss
            
            # 2. 反向传播
            loss.backward()
            
            # 3. 更新参数
            optimizer.step()
            optimizer.zero_grad()
            
            total_loss += loss.item()
        
        # 打印训练信息
        avg_loss = total_loss / len(train_dataloader)
        print(f"Epoch {epoch+1}, Loss: {avg_loss:.4f}")
```

## 三、全量微调（Full Fine-tuning）

### 什么是全量微调？

**全量微调 = 更新模型的所有参数**

```
全量微调的过程：

输入：预训练模型（比如 LLaMA-7B，70亿参数）
训练：更新所有70亿个参数
输出：微调后的模型

特点：
  - 更新所有参数
  - 效果最好
  - 需要大量显存
  - 训练时间长
```

### 用具体数字理解

```
LLaMA-7B 的参数量：70亿（7B）

全量微调的显存需求：
  模型参数：7B × 4字节 = 28GB（FP32）
  优化器状态：28GB × 2 = 56GB（Adam需要存动量和方差）
  梯度：28GB
  激活值：约10-20GB
  
  总计：约120-130GB 显存

需要 A100 80GB 显卡，至少2张！
```

### 全量微调的代码

```python
from transformers import AutoModelForCausalLM, AutoTokenizer

# 加载模型
model = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-2-7b-hf")
tokenizer = AutoTokenizer.from_pretrained("meta-llama/Llama-2-7b-hf")

# 所有参数都参与训练
for param in model.parameters():
    param.requires_grad = True  # 允许梯度计算

# 训练
optimizer = AdamW(model.parameters(), lr=2e-5)
train(model, train_dataloader, optimizer, num_epochs=3)
```

### 全量微调的优缺点

```
优点：
  1. 效果最好
  2. 可以充分适应新任务
  3. 不需要额外的参数

缺点：
  1. 需要大量显存（120GB+）
  2. 训练时间长
  3. 成本高
  4. 容易过拟合（如果数据少）
```

## 四、LoRA（低秩适应）

### 什么是 LoRA？

**LoRA = Low-Rank Adaptation（低秩适应）**

```
LoRA 的核心思想：
  不更新所有参数
  而是在原始权重旁边加一个小的"旁路"
  只训练这个旁路

用比喻理解：
  全量微调：重新装修整个房子
  LoRA：只在墙上挂几幅画
```

### LoRA 的数学原理

```
原始的权重更新：
  W_new = W_old + ΔW
  
  其中 ΔW 和 W_old 形状相同（比如 768×768）
  参数量 = 768 × 768 = 589,824

LoRA 的权重更新：
  W_new = W_old + ΔW
  ΔW = A × B
  
  其中 A 是 (768, r)，B 是 (r, 768)
  r 是一个很小的数（比如 8）
  
  参数量 = 768 × 8 + 8 × 768 = 12,288
  
  参数量减少了 48 倍！
```

### 用具体数字理解

```
假设原始权重矩阵 W：768 × 768

全量微调：
  需要更新的参数 = 768 × 768 = 589,824

LoRA（r=8）：
  A 矩阵：768 × 8 = 6,144
  B 矩阵：8 × 768 = 6,144
  需要更新的参数 = 6,144 + 6,144 = 12,288
  
  参数量 = 589,824 / 12,288 = 48倍
  减少了 48 倍！
```

### LoRA 的图示

```
┌─────────────────────────────────────────────────────────────┐
│                    LoRA 结构                                │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  原始权重 W（冻结，不更新）                                 │
│  ┌─────────────────────────────────────────────────────┐   │
│  │                                                     │   │
│  │                    W (768×768)                      │   │
│  │                                                     │   │
│  └─────────────────────────────────────────────────────┘   │
│                          ↓                                  │
│                      输出 = W × 输入                        │
│                                                             │
│  ─────────────────────────────────────────────────────────  │
│                                                             │
│  LoRA 旁路（可训练）                                        │
│  ┌─────────────────────────────────────────────────────┐   │
│  │                                                     │   │
│  │  输入 → A (768×8) → B (8×768) → ΔW → 输出          │   │
│  │                                                     │   │
│  └─────────────────────────────────────────────────────┘   │
│                          ↓                                  │
│                      输出 = A × B × 输入                    │
│                                                             │
│  ─────────────────────────────────────────────────────────  │
│                                                             │
│  最终输出 = W × 输入 + A × B × 输入                        │
│           = (W + A × B) × 输入                              │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### LoRA 的代码实现

```python
from peft import LoraConfig, get_peft_model, TaskType

# LoRA 配置
lora_config = LoraConfig(
    task_type=TaskType.CAUSAL_LM,  # 任务类型：因果语言模型
    r=8,                           # 低秩矩阵的秩
    lora_alpha=32,                 # 缩放因子
    lora_dropout=0.05,             # Dropout 概率
    target_modules=["q_proj", "v_proj"],  # 要应用 LoRA 的模块
)

# 加载基座模型
model = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-2-7b-hf")

# 应用 LoRA
model = get_peft_model(model, lora_config)

# 查看可训练参数量
model.print_trainable_parameters()
# 输出：trainable params: 4,194,304 || all params: 6,742,609,920 || trainable%: 0.06

# 训练（只更新 LoRA 参数）
optimizer = AdamW(model.parameters(), lr=2e-4)
train(model, train_dataloader, optimizer, num_epochs=3)
```

### LoRA 的参数选择

```
r（秩）的选择：
  - r=4：参数最少，效果一般
  - r=8：常用，平衡效果和效率
  - r=16：参数较多，效果更好
  - r=64：参数很多，接近全量微调

lora_alpha（缩放因子）：
  - 通常设为 r 的 2-4 倍
  - 比如 r=8，lora_alpha=32

target_modules（目标模块）：
  - 通常选择注意力层的 Q、K、V、O
  - 也可以加上前馈网络
```

### LoRA 的优缺点

```
优点：
  1. 参数量小（减少几十倍）
  2. 显存需求低
  3. 训练速度快
  4. 效果接近全量微调
  5. 可以保存多个 LoRA，切换任务

缺点：
  1. 效果可能略差于全量微调
  2. 需要选择合适的 r 和 target_modules
```

## 五、QLoRA（量化 LoRA）

### 什么是 QLoRA？

**QLoRA = Quantized LoRA（量化 LoRA）**

```
QLoRA 的核心思想：
  在 LoRA 基础上，把基座模型量化成 4-bit
  进一步减少显存需求

用比喻理解：
  全量微调：用高清图片训练（占空间大）
  LoRA：用压缩图片训练（占空间小）
  QLoRA：用更小的压缩图片训练（占空间更小）
```

### QLoRA 的技术细节

```
┌─────────────────────────────────────────────────────────────┐
│                    QLoRA 的三个技术                         │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. 4-bit 量化（NF4）                                       │
│     - 把模型权重从 FP16 量化成 4-bit                       │
│     - 显存减少 4 倍                                         │
│                                                             │
│  2. 双重量化（Double Quantization）                        │
│     - 对量化常数再进行量化                                 │
│     - 进一步节省显存                                        │
│                                                             │
│  3. 分页优化器（Paged Optimizers）                          │
│     - 使用 CPU 内存来处理显存溢出                           │
│     - 避免显存不足崩溃                                      │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 显存需求对比

```
┌─────────────────────────────────────────────────────────────┐
│              显存需求对比（LLaMA-7B）                        │
├─────────────────────────────────────────────────────────────┤
│  方法          模型精度    显存需求    能用的显卡           │
├─────────────────────────────────────────────────────────────┤
│  全量微调      FP16        120GB+      A100 80GB × 2       │
│  LoRA          FP16        28GB        A100 40GB           │
│  QLoRA         4-bit       6GB         RTX 3060            │
└─────────────────────────────────────────────────────────────┘

QLoRA 让个人电脑也能微调大模型！
```

### QLoRA 的代码实现

```python
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training

# 量化配置
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,                  # 4-bit 量化
    bnb_4bit_quant_type="nf4",          # NF4 量化类型
    bnb_4bit_compute_dtype=torch.float16,  # 计算精度
    bnb_4bit_use_double_quant=True,     # 双重量化
)

# 加载量化模型
model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-2-7b-hf",
    quantization_config=bnb_config,
    device_map="auto",
)

# 准备模型用于 k-bit 训练
model = prepare_model_for_kbit_training(model)

# LoRA 配置
lora_config = LoraConfig(
    r=8,
    lora_alpha=32,
    target_modules=["q_proj", "v_proj"],
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM",
)

# 应用 LoRA
model = get_peft_model(model, lora_config)

# 查看可训练参数
model.print_trainable_parameters()
# 输出：trainable params: 4,194,304 || all params: 3,508,801,536 || trainable%: 0.12

# 训练
optimizer = AdamW(model.parameters(), lr=2e-4)
train(model, train_dataloader, optimizer, num_epochs=3)
```

### QLoRA 的显存计算

```
LLaMA-7B 的 QLoRA 显存需求：

模型权重（4-bit）：7B × 0.5字节 = 3.5GB
LoRA 参数：4M × 2字节 = 8MB
优化器状态：4M × 4字节 × 2 = 32MB
梯度：4M × 2字节 = 8MB
激活值：约1-2GB

总计：约5-6GB

一张 RTX 3060（12GB）就够了！
```

## 七、SFT（有监督微调）

### 什么是 SFT？

**SFT = Supervised Fine-Tuning（有监督微调）**

```
SFT 的过程：

输入：基座模型 + 人工标注的数据

数据格式：
  输入：用户的问题
  输出：期望的回答（人工标注）

训练：让模型学习输入→输出的映射

输出：助手模型
```

### SFT 的训练数据

```
训练数据（人工标注）：

样本1：
  输入："你好"
  输出："你好！有什么可以帮你的吗？"

样本2：
  输入："1+1等于几？"
  输出："1+1等于2。"

样本3：
  输入："请介绍一下北京。"
  输出："北京是中国的首都，也是中国的政治、文化中心。"
```

### SFT 的损失计算

```python
def compute_sft_loss(logits, labels, input_length):
    """
    计算 SFT 损失
    
    关键：只计算回答部分的损失，不计算问题部分
    """
    # logits: 模型输出，形状 (batch_size, seq_len, vocab_size)
    # labels: 目标，形状 (batch_size, seq_len)
    # input_length: 输入（问题）的长度
    
    # 把问题部分的标签设为 -100（不计算损失）
    labels[:, :input_length] = -100
    
    # 计算损失（PyTorch 会忽略 -100 的位置）
    loss = F.cross_entropy(
        logits.view(-1, logits.size(-1)),
        labels.view(-1),
        ignore_index=-100
    )
    
    return loss
```

## 八、RLHF（人类反馈强化学习）

### RLHF 的三个阶段

```
┌─────────────────────────────────────────────────────────────┐
│                    RLHF 的三个阶段                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  阶段1：SFT（有监督微调）                                   │
│    - 用人工标注的数据训练                                   │
│    - 得到一个初始的助手模型                                 │
│                                                             │
│  阶段2：训练奖励模型（Reward Model）                        │
│    - 收集人类对回答的排序                                   │
│    - 训练一个模型来预测人类偏好                             │
│                                                             │
│  阶段3：强化学习优化（PPO）                                 │
│    - 用奖励模型来指导助手模型的训练                         │
│    - 让助手模型生成更符合人类偏好的回答                     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 阶段2：训练奖励模型

```
收集人类偏好数据：

问题："请介绍一下北京。"

回答A："北京是中国的首都，有着悠久的历史。"
回答B："北京是中国的首都，位于华北平原，面积16410平方公里..."
回答C："北京是一个城市。"

人类排序：A > B > C（A最好，C最差）

训练奖励模型：
  输入：问题 + 回答
  输出：分数（越高越好）
  
  损失函数：让 A 的分数 > B 的分数 > C 的分数
```

### 阶段3：PPO 优化

```
PPO（Proximal Policy Optimization）的过程：

1. 助手模型生成回答
2. 奖励模型给回答打分
3. 用 PPO 算法更新助手模型
   - 如果分数高：鼓励这种回答方式
   - 如果分数低：避免这种回答方式

重复这个过程，直到助手模型的回答让奖励模型给高分
```

## 九、总结

### 微调方法对比

| 方法 | 核心思想 | 优点 | 缺点 |
|------|----------|------|------|
| 全量微调 | 更新所有参数 | 效果最好 | 显存需求大 |
| LoRA | 只更新低秩旁路 | 显存需求小 | 效果略差 |
| QLoRA | 量化 + LoRA | 显存需求最小 | 精度损失 |
| SFT | 用标注数据训练 | 简单直接 | 需要标注数据 |
| RLHF | 用人类反馈优化 | 更符合偏好 | 实现复杂 |

### 选择建议

```
┌─────────────────────────────────────────────────────────────┐
│                    如何选择微调方法？                        │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  有充足资源（多张 A100）：                                   │
```

## 练习答案

### 练习1答案

1. **核心思想**：不更新所有参数，而是在原始权重旁边加一个小的"旁路"，只训练这个旁路。
2. **为什么减少参数**：原始权重矩阵是 d×d，LoRA 把它分解成 d×r 和 r×d（r 很小），参数量从 d² 减少到 2dr。
3. **r 的选择**：r=4 参数最少效果一般，r=8 常用，r=16 效果更好，r=64 接近全量微调。

### 练习2答案

1. **区别**：QLoRA 在 LoRA 基础上把基座模型量化成 4-bit，进一步减少显存。
2. **为什么更省显存**：模型权重从 FP16（2字节）变成 4-bit（0.5字节），显存减少 4 倍。
3. **能微调多大模型**：RTX 3060 12GB 可以微调 7B 模型。

### 练习3答案

1. **8 张 A100**：可以全量微调 70B 模型，或者用 LoRA 微调更大的模型
2. **1 张 A100 40GB**：可以用 LoRA 微调 7B-13B 模型
3. **1 张 RTX 3060 12GB**：只能用 QLoRA 微调 7B 模型

## 十、深入理解：SFT 到底做了什么？

### SFT 的核心问题

**问题：SFT 是用新数据重新训练一遍吗？需要新的网络结构吗？**

**答案：不需要新的网络结构！就是用新数据继续训练同一个模型。**

### SFT vs 预训练的对比

```
┌─────────────────────────────────────────────────────────────┐
│              SFT vs 预训练 详细对比                          │
├─────────────────────────────────────────────────────────────┤
│  方面            预训练                SFT                   │
├─────────────────────────────────────────────────────────────┤
│  模型结构        Transformer解码器     同一个解码器（不变！）│
│  训练方式        预测下一个词          同样是预测下一个词    │
│  数据            海量无标注文本        少量有标注对话        │
│  损失函数        交叉熵                同样的交叉熵          │
│  优化器          Adam                  同样的Adam            │
│  更新参数        所有参数              所有参数（或LoRA）    │
└─────────────────────────────────────────────────────────────┘

唯一变的是：数据！
```

### 用具体例子理解

```
预训练数据：
  "今天天气真好，适合出去玩。"
  
  训练样本：
    输入："今天" → 目标："天气"
    输入："今天 天气" → 目标："真"
    输入："今天 天气 真" → 目标："好"

────────────────────────────────────────

SFT 数据：
  "用户：今天天气怎么样？ 助手：今天天气很好，适合出去玩。"
  
  训练样本：
    输入："用户：今天天气怎么样？ 助手：" → 目标："今天天气很好，适合出去玩。"

────────────────────────────────────────

训练方式完全一样！都是预测下一个词！
```

### 为什么 SFT 能改变模型行为？

```
预训练时：
  模型看到 "今天天气" → 可能预测 "真"、"不错"、"很"...
  模型学会了续写文本

SFT 时：
  模型看到 "用户：今天天气怎么样？ 助手：" → 预测 "今天天气很好"
  模型学会了：看到"用户：...助手："这种格式，就要回答问题

通过大量对话数据的训练，模型学会了：
  1. 看到"用户："开头，就知道是问题
  2. 看到"助手："，就知道要开始回答
  3. 回答要简洁、准确、有帮助
```

### SFT 的数据格式详解

```python
# 预训练数据格式（简单的文本）
pretrain_data = "今天天气真好，适合出去玩。我喜欢在公园散步。"

# SFT 数据格式（对话格式）
sft_data = {
    "conversations": [
        {"role": "user", "content": "今天天气怎么样？"},
        {"role": "assistant", "content": "今天天气很好，适合出去玩。"},
        {"role": "user", "content": "那应该做什么呢？"},
        {"role": "assistant", "content": "可以去公园散步，享受阳光。"}
    ]
}

# 训练时，把对话拼接成一个序列
# "用户：今天天气怎么样？ 助手：今天天气很好，适合出去玩。用户：那应该做什么呢？ 助手：可以去公园散步，享受阳光。"
```

### SFT 的损失计算

```python
def compute_sft_loss(model, conversations):
    """
    SFT 的损失计算
    
    关键：只计算助手回答部分的损失
    """
    # 把对话拼接成一个序列
    full_text = ""
    for turn in conversations:
        if turn["role"] == "user":
            full_text += f"用户：{turn['content']} 助手："
        else:
            full_text += turn['content']
    
    # 分词
    tokens = tokenizer.encode(full_text)
    
    # 构造标签
    # 用户部分的标签设为 -100（不计算损失）
    # 只计算助手部分的损失
    labels = [-100] * len(tokens)
    
    # 找到助手回答的位置，设置正确的标签
    # （实际实现会更复杂，这里简化说明）
    
    # 前向传播
    logits = model(torch.tensor([tokens]))
    
    # 计算损失（只计算助手部分）
    loss = F.cross_entropy(
        logits.view(-1, logits.size(-1)),
        torch.tensor([labels]).view(-1),
        ignore_index=-100
    )
    
    return loss
```

### 为什么只计算助手部分的损失？

```
如果计算所有部分的损失：
  模型会学习续写整个对话（包括用户的问题）
  这不是我们想要的

只计算助手部分的损失：
  模型只学习怎么回答问题
  不会学习怎么续写用户的问题
  这才是我们想要的！
```

## 十一、深入理解：RLHF 到底做了什么？

### RLHF 的核心问题

**问题：RLHF 和 SFT 有什么区别？为什么需要 RLHF？**

**答案：SFT 告诉模型"正确答案是什么"，RLHF 告诉模型"哪个答案更好"。**

### SFT 的局限性

```
SFT 的问题：

1. 只能学习"正确答案"
   - 有些问题没有唯一正确答案
   - 比如："写一首诗"，有很多好的写法
   
2. 难以学习"风格"
   - 怎样的回答更友好？
   - 怎样的回答更有帮助？
   - 这些难以用"正确答案"来定义
   
3. 难以避免"有害内容"
   - SFT 只能学习"应该说什么"
   - 难以学习"不应该说什么"
```

### RLHF 的优势

```
RLHF 能做到：

1. 学习"更好"的回答
   - 不只是"正确"，还要"更好"
   - 比如：更简洁、更友好、更有帮助
   
2. 学习"风格"
   - 通过人类偏好来学习
   - 人类喜欢的回答 → 鼓励
   - 人类不喜欢的回答 → 避免
   
3. 避免"有害内容"
   - 人类会标注"有害"的回答
   - 模型学会避免这些回答
```

### RLHF 的详细流程

```
┌─────────────────────────────────────────────────────────────┐
│                    RLHF 详细流程                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  阶段1：SFT（有监督微调）                                   │
│  ─────────────────────────────────────────────────────────  │
│    输入：基座模型 + 对话数据                                │
│    输出：SFT 模型（会对话，但可能不够好）                   │
│                                                             │
│  阶段2：训练奖励模型（Reward Model）                        │
│  ─────────────────────────────────────────────────────────  │
│    输入：同一个问题的多个回答                               │
│    人类标注：哪个回答更好（排序）                           │
│    训练：奖励模型学习预测人类偏好                           │
│    输出：奖励模型（可以给回答打分）                         │
│                                                             │
│  阶段3：PPO 优化（强化学习）                                │
│  ─────────────────────────────────────────────────────────  │
│    输入：SFT 模型 + 奖励模型                               │
│    过程：                                                   │
│      1. SFT 模型生成回答                                   │
│      2. 奖励模型给回答打分                                 │
│      3. 根据分数调整 SFT 模型                              │
│    输出：最终的助手模型（更符合人类偏好）                   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 阶段2：训练奖励模型（详细）

```
收集人类偏好数据：

问题："请介绍一下北京。"

生成4个回答：
  A："北京是中国的首都，有着悠久的历史和丰富的文化遗产。"
  B："北京是中国的首都，位于华北平原，面积16410平方公里，人口2154万。"
  C："北京是一个城市。"
  D："北京是中国的首都，有着悠久的历史。它位于华北平原，是中国的政治、文化中心。"

人类排序：A > D > B > C

原因：
  A：简洁、准确、有帮助 ✓✓✓
  D：准确但有点长 ✓✓
  B：准确但太长，像在读维基百科 ✓
  C：太简短，没有帮助 ✗
```

### 奖励模型的训练

```python
class RewardModel(nn.Module):
    """奖励模型"""
    
    def __init__(self, base_model):
        super().__init__()
        self.base_model = base_model
        self.reward_head = nn.Linear(hidden_size, 1)  # 输出一个分数
    
    def forward(self, input_ids):
        # 获取模型输出
        outputs = self.base_model(input_ids)
        hidden = outputs.last_hidden_state[:, -1, :]  # 取最后一个位置
        
        # 计算奖励分数
        reward = self.reward_head(hidden)
        
        return reward

def train_reward_model(reward_model, preference_data):
    """
    训练奖励模型
    
    preference_data: [(问题, 好回答, 差回答), ...]
    """
    optimizer = Adam(reward_model.parameters(), lr=1e-5)
    
    for question, good_answer, bad_answer in preference_data:
        # 计算两个回答的分数
        score_good = reward_model(question + good_answer)
        score_bad = reward_model(question + bad_answer)
        
        # 损失函数：好回答的分数应该比差回答高
        # 使用 Bradley-Terry 模型
        loss = -torch.log(torch.sigmoid(score_good - score_bad))
        
        # 反向传播
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
```

### 阶段3：PPO 优化（详细）

```
PPO（Proximal Policy Optimization）的过程：

1. 采样
   - 从训练数据中取一个问题
   - SFT 模型生成一个回答
   
2. 评分
   - 奖励模型给回答打分
   - 比如：分数 = 0.8
   
3. 计算优势
   - 如果分数高 → 优势为正（鼓励这种回答）
   - 如果分数低 → 优势为负（避免这种回答）
   
4. 更新模型
   - 用 PPO 算法更新 SFT 模型
   - 让模型更倾向于生成高分的回答
   
5. 重复
   - 重复 1-4，直到模型的回答让奖励模型满意
```

### PPO 的代码示例

```python
def ppo_update(assistant_model, reward_model, prompts, ppo_config):
    """
    PPO 更新
    """
    optimizer = Adam(assistant_model.parameters(), lr=ppo_config.lr)
    
    for prompt in prompts:
        # 1. 生成回答
        response = assistant_model.generate(prompt)
        
        # 2. 计算奖励
        reward = reward_model.score(prompt, response)
        
        # 3. 计算旧策略的概率
        old_logprobs = assistant_model.logprob(prompt, response)
        
        # 4. PPO 更新（多次迭代）
        for _ in range(ppo_config.ppo_epochs):
            # 计算新策略的概率
            new_logprobs = assistant_model.logprob(prompt, response)
            
            # 计算比率
            ratio = torch.exp(new_logprobs - old_logprobs)
            
            # 计算优势（简化版）
            advantage = reward - ppo_config.baseline
            
            # PPO 损失
            surr1 = ratio * advantage
            surr2 = torch.clamp(ratio, 1-ppo_config.eps, 1+ppo_config.eps) * advantage
            loss = -torch.min(surr1, surr2).mean()
            
            # 更新
            optimizer.zero_grad()
            loss.backward()
            optimizer.step()
```

## 十二、总结：SFT vs RLHF

### 核心区别

```
┌─────────────────────────────────────────────────────────────┐
│                    SFT vs RLHF 核心区别                     │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  SFT（有监督微调）：                                        │
```

### 用比喻理解

```
SFT = 老师告诉你答案
  老师："1+1=2，记住！"
  学生：记住了，1+1=2

RLHF = 老师告诉你哪个更好
  老师："这两个答案，A 比 B 好。"
  学生：明白了，我以后多写 A 这样的答案

SFT 学习"正确性"

```

### 为什么需要两者？

```
只有 SFT 的问题：
  - 模型会回答问题，但可能不够好
  - 可能太长、太短、不够友好
  - 可能会胡说八道

只有 RLHF 的问题：
  - 模型可能不知道怎么回答问题
  - 需要先有基本的对话能力

SFT + RLHF：
  - SFT：学会基本的对话能力
  - RLHF：让对话能力更强、更符合人类偏好
```

### PPO（Proximal Policy Optimization）详解

#### PPO 的完整流程

```
┌─────────────────────────────────────────────────────────────┐
│                    PPO 完整流程                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  准备工作：                                                 │
│    - SFT 模型（待优化）                                     │
│    - 奖励模型（打分用）                                     │
│    - 参考模型（SFT模型的副本，冻结不动）                    │
│                                                             │
│  循环训练：                                                 │
│    ┌─────────────────────────────────────────────────────┐  │
│    │  步骤1：采样                                        │  │
│    │    - 取一个问题 prompt                              │  │
│    │    - SFT 模型生成回答 response                      │  │
│    └─────────────────────────────────────────────────────┘  │
│                          ↓                                  │
│    ┌─────────────────────────────────────────────────────┐  │
│    │  步骤2：评分                                        │  │
│    │    - 奖励模型给 (prompt, response) 打分             │  │
│    │    - 得到奖励值 reward                              │  │
│    └─────────────────────────────────────────────────────┘  │
│                          ↓                                  │
│    ┌─────────────────────────────────────────────────────┐  │
│    │  步骤3：计算 KL 散度                                │  │
│    │    - 比较 SFT 模型和参考模型的回答概率              │  │
│    │    - 防止 SFT 模型偏离太远                          │  │
│    └─────────────────────────────────────────────────────┘  │
│                          ↓                                  │
│    ┌─────────────────────────────────────────────────────┐  │
│    │  步骤4：计算最终奖励                                │  │
│    │    - final_reward = reward - β × KL                 │  │
│    │    - β 是惩罚系数，防止偏离太远                     │  │
│    └─────────────────────────────────────────────────────┘  │
│                          ↓                                  │
│    ┌─────────────────────────────────────────────────────┐  │
│    │  步骤5：PPO 更新                                    │  │
│    │    - 用 final_reward 更新 SFT 模型                 │  │
│    │    - 使用 PPO 的裁剪机制，防止更新太大              │  │
│    └─────────────────────────────────────────────────────┘  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

#### PPO 的数学原理

```
PPO 的目标函数：

L^PPO = E[min(r_t(θ) × A_t, clip(r_t(θ), 1-ε, 1+ε) × A_t)]

其中：
  r_t(θ) = π_θ(a_t|s_t) / π_θ_old(a_t|s_t)  （新旧策略的概率比）
  A_t = reward - baseline  （优势函数）
  ε = 0.2  （裁剪参数）

通俗理解：
  - 如果回答好（A_t > 0）：鼓励生成类似回答，但不能太多
  - 如果回答差（A_t < 0）：避免生成类似回答，但不能太多
  - clip 机制防止更新太大，保持稳定
```

#### PPO 的代码实现

```python
class PPOTrainer:
    """PPO 训练器"""
    
    def __init__(self, sft_model, reward_model, ref_model, tokenizer):
        self.sft_model = sft_model          # 待优化的模型
        self.reward_model = reward_model    # 奖励模型
        self.ref_model = ref_model          # 参考模型（冻结）
        self.tokenizer = tokenizer
        
        # PPO 参数
        self.clip_epsilon = 0.2     # 裁剪参数
        self.kl_coeff = 0.1         # KL 惩罚系数
        self.gamma = 0.99           # 折扣因子
        self.lam = 0.95             # GAE 参数
    
    def generate_response(self, prompt):
        """生成回答"""
        inputs = self.tokenizer(prompt, return_tensors="pt")
        
        with torch.no_grad():
            response = self.sft_model.generate(
                **inputs,
                max_length=512,
                do_sample=True,
                temperature=0.7
            )
        
        return response
    
    def compute_reward(self, prompt, response):
        """计算奖励"""
        # 奖励模型打分
        reward = self.reward_model.score(prompt, response)
        
        # 计算 KL 散度
        sft_logprobs = self.sft_model.logprob(prompt, response)
        ref_logprobs = self.ref_model.logprob(prompt, response)
        kl = sft_logprobs - ref_logprobs
        
        # 最终奖励 = 奖励 - KL 惩罚
        final_reward = reward - self.kl_coeff * kl
        
        return final_reward
    
    def ppo_update(self, prompt, response, old_logprobs, reward):
        """PPO 更新"""
        
        # 计算新策略的概率
        new_logprobs = self.sft_model.logprob(prompt, response)
        
        # 计算概率比
        ratio = torch.exp(new_logprobs - old_logprobs)
        
        # 计算优势
        advantage = reward  # 简化版
        
        # PPO 裁剪损失
        surr1 = ratio * advantage
        surr2 = torch.clamp(ratio, 1-self.clip_epsilon, 1+self.clip_epsilon) * advantage
        loss = -torch.min(surr1, surr2).mean()
        
        # 更新
        self.optimizer.zero_grad()
        loss.backward()
        self.optimizer.step()
        
        return loss.item()
    
    def train(self, prompts, num_epochs=3):
        """训练循环"""
        
        for epoch in range(num_epochs):
            total_reward = 0
            
            for prompt in prompts:
                # 步骤1：生成回答
                response = self.generate_response(prompt)
                
                # 步骤2：计算奖励
                reward = self.compute_reward(prompt, response)
                
                # 步骤3：记录旧概率
                old_logprobs = self.sft_model.logprob(prompt, response).detach()
                
                # 步骤4：PPO 更新（多次迭代）
                for _ in range(4):  # ppo_epochs
                    loss = self.ppo_update(prompt, response, old_logprobs, reward)
                
                total_reward += reward.item()
            
            print(f"Epoch {epoch+1}, Avg Reward: {total_reward/len(prompts):.4f}")
```

```
  2. 可以优化复杂的目标

缺点：
```

### DPO（Direct Preference Optimization）详解

#### DPO 的核心思想

**DPO 的核心：不需要训练奖励模型，直接用偏好数据优化模型！**

```
PPO 的流程：
  1. 收集偏好数据
  2. 训练奖励模型
  3. 用奖励模型指导优化

DPO 的流程：
  1. 收集偏好数据
  2. 直接用偏好数据优化模型（跳过奖励模型）

DPO 更简单！
```

#### DPO 的数学原理

```
DPO 的损失函数：

L^DPO = -E[log σ(β × (log π_θ(y_w|x) / π_ref(y_w|x) - log π_θ(y_l|x) / π_ref(y_l|x)))]

其中：
  x = 问题
  y_w = 好的回答（人类偏好的）
  y_l = 差的回答（人类不偏好的）
  π_θ = 当前模型
  π_ref = 参考模型
  β = 温度参数
  σ = sigmoid 函数

通俗理解：
  让模型给好回答的概率更高
  让模型给差回答的概率更低
```

#### DPO 的代码实现

```python
class DPOTrainer:
    """DPO 训练器"""
    
    def __init__(self, model, ref_model, tokenizer, beta=0.1):
        self.model = model              # 待优化的模型
        self.ref_model = ref_model      # 参考模型（冻结）
        self.tokenizer = tokenizer
        self.beta = beta                # 温度参数
        
        self.optimizer = Adam(model.parameters(), lr=5e-7)
    
    def compute_loss(self, prompt, chosen, rejected):
        """
        计算 DPO 损失
        
        参数：
          prompt: 问题
          chosen: 好的回答
          rejected: 差的回答
        """
        # 计算当前模型的概率
        chosen_logprobs = self.model.logprob(prompt, chosen)
        rejected_logprobs = self.model.logprob(prompt, rejected)
        
        # 计算参考模型的概率
        with torch.no_grad():
            ref_chosen_logprobs = self.ref_model.logprob(prompt, chosen)
            ref_rejected_logprobs = self.ref_model.logprob(prompt, rejected)
        
        # 计算 log 概率比
        chosen_ratio = chosen_logprobs - ref_chosen_logprobs
        rejected_ratio = rejected_logprobs - ref_rejected_logprobs
        
        # DPO 损失
        loss = -F.logsigmoid(self.beta * (chosen_ratio - rejected_ratio)).mean()
        
        return loss
    
    def train(self, preference_data, num_epochs=3):
        """
        训练循环
        
        preference_data: [(prompt, chosen, rejected), ...]
        """
        self.model.train()
        
        for epoch in range(num_epochs):
            total_loss = 0
            
            for prompt, chosen, rejected in preference_data:
                # 计算损失
                loss = self.compute_loss(prompt, chosen, rejected)
                
                # 更新
                self.optimizer.zero_grad()
                loss.backward()
                self.optimizer.step()
                
                total_loss += loss.item()
            
            print(f"Epoch {epoch+1}, Loss: {total_loss/len(preference_data):.4f}")
```

### GRPO（Group Relative Policy Optimization）详解

#### GRPO 的核心思想

**GRPO 的核心：用组内相对排名来优化模型，不需要奖励模型！**

```
GRPO 的创新点：
  1. 不需要奖励模型
  2. 不需要参考模型
  3. 用组内相对排名来计算优势
  4. 更高效，更稳定
```

#### GRPO 的完整流程

```
┌─────────────────────────────────────────────────────────────┐
│                    GRPO 完整流程                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  步骤1：采样                                                │
│    - 取一个问题 prompt                                      │
│    - 模型生成 G 个回答（比如 G=8）                          │
│    - response_1, response_2, ..., response_G                │
│                                                             │
│  步骤2：评分                                                │
│    - 用规则或奖励模型给每个回答打分                         │
│    - score_1, score_2, ..., score_G                         │
│                                                             │
│  步骤3：计算组内相对优势                                    │
│    - 在这 G 个回答中，计算每个回答的相对排名                │
│    - advantage_i = (score_i - mean(scores)) / std(scores)   │
│    - 排名高的回答，优势为正                                 │
│    - 排名低的回答，优势为负                                 │
│                                                             │
│  步骤4：策略更新                                            │
│    - 用相对优势来更新模型                                   │
│    - 鼓励生成高排名的回答                                   │
│    - 避免生成低排名的回答                                   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

#### GRPO 的数学原理

```
GRPO 的损失函数：

L^GRPO = -E[Σ_i min(r_i(θ) × A_i, clip(r_i(θ), 1-ε, 1+ε) × A_i)]

其中：
  G = 组大小（比如8）
  r_i(θ) = π_θ(response_i) / π_θ_old(response_i)  （概率比）
  A_i = (score_i - mean(scores)) / std(scores)  （组内相对优势）

关键区别：
  PPO 的优势：reward - baseline（需要奖励模型）
  GRPO 的优势：组内相对排名（不需要奖励模型）
```

#### GRPO 的代码实现

```python
class GRPOTrainer:
    """GRPO 训练器"""
    
    def __init__(self, model, tokenizer, group_size=8, clip_epsilon=0.2):
        self.model = model
        self.tokenizer = tokenizer
        self.group_size = group_size      # 组大小
        self.clip_epsilon = clip_epsilon  # 裁剪参数
        
        self.optimizer = Adam(model.parameters(), lr=1e-6)
    
    def generate_group(self, prompt):
        """生成一组回答"""
        responses = []
        
        for _ in range(self.group_size):
            response = self.model.generate(
                prompt,
                max_length=512,
                do_sample=True,
                temperature=0.7
            )
            responses.append(response)
        
        return responses
    
    def compute_scores(self, prompt, responses):
        """计算每个回答的分数"""
        scores = []
        
        for response in responses:
            # 可以用规则打分，或者用奖励模型
            score = self.score_function(prompt, response)
            scores.append(score)
        
        return torch.tensor(scores)
    
    def compute_advantages(self, scores):
        """计算组内相对优势"""
        mean = scores.mean()
        std = scores.std()
        
        advantages = (scores - mean) / (std + 1e-8)
        
        return advantages
    
    def grpo_update(self, prompt, responses, old_logprobs, advantages):
        """GRPO 更新"""
        
        total_loss = 0
        
        for i, response in enumerate(responses):
            # 计算新概率
            new_logprobs = self.model.logprob(prompt, response)
            
            # 计算概率比
            ratio = torch.exp(new_logprobs - old_logprobs[i])
            
            # GRPO 裁剪损失
            surr1 = ratio * advantages[i]
            surr2 = torch.clamp(ratio, 1-self.clip_epsilon, 1+self.clip_epsilon) * advantages[i]
            loss = -torch.min(surr1, surr2)
            
            total_loss += loss
        
        # 平均损失
        total_loss = total_loss / self.group_size
        
        # 更新
        self.optimizer.zero_grad()
        total_loss.backward()
        self.optimizer.step()
        
        return total_loss.item()
    
    def train(self, prompts, num_epochs=3):
        """训练循环"""
        
        for epoch in range(num_epochs):
            total_reward = 0
            
            for prompt in prompts:
                # 步骤1：生成一组回答
                responses = self.generate_group(prompt)
                
                # 步骤2：计算分数
                scores = self.compute_scores(prompt, responses)
                
                # 步骤3：计算相对优势
                advantages = self.compute_advantages(scores)
                
                # 步骤4：记录旧概率
                old_logprobs = []
                for response in responses:
                    logprob = self.model.logprob(prompt, response).detach()
                    old_logprobs.append(logprob)
                
                # 步骤5：GRPO 更新
                loss = self.grpo_update(prompt, responses, old_logprobs, advantages)
                
                total_reward += scores.mean().item()
            
            print(f"Epoch {epoch+1}, Avg Reward: {total_reward/len(prompts):.4f}")
```

## 十四、总结：强化学习算法

### 算法对比总结

| 算法 | 核心思想 | 优点 | 缺点 | 使用模型 |
|------|----------|------|------|----------|
| PPO | 用奖励模型指导优化 | 效果好 | 复杂、不稳定 | ChatGPT |
| DPO | 直接用偏好数据优化 | 简单、稳定 | 需要偏好数据 | LLaMA-2 |
| GRPO | 用组内相对排名优化 | 高效、稳定 | 需要多次采样 | DeepSeek |

### 发展趋势

```
PPO → DPO → GRPO

趋势：
  1. 越来越简单（不需要奖励模型）
  2. 越来越稳定（训练更容易）
  3. 越来越高效（计算成本更低）
```
