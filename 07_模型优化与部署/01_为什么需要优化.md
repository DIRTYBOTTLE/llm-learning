# 7.1 为什么需要优化

> 大模型虽好，但用起来太贵太慢！

## 从你已经知道的开始

在前几章，你学了：
- 大模型有几十亿甚至上千亿参数
- 训练大模型需要大量资源
- 使用大模型也需要资源

**这一节，我们来看看为什么需要优化！**

---

## 一、大模型的资源需求

### 模型大小

```
┌─────────────────────────────────────────────────────────────┐
│                    常见模型的大小                            │
├─────────────────────────────────────────────────────────────┤
│  模型          参数量      FP16大小     INT4大小            │
├─────────────────────────────────────────────────────────────┤
│  GPT-2         1.5亿       3GB          0.75GB              │
│  LLaMA-7B      70亿        14GB         3.5GB               │
│  LLaMA-13B     130亿       26GB         6.5GB               │
│  LLaMA-70B     700亿       140GB        35GB                │
│  GPT-3         1750亿      350GB        87.5GB              │
└─────────────────────────────────────────────────────────────┘
```

### 显存需求

```
运行一个模型需要的显存：

1. 模型权重
   FP16：参数量 × 2 字节
   INT4：参数量 × 0.5 字节

2. KV Cache
   用于加速生成，占用额外显存

3. 激活值
   前向传播的中间结果

4. 系统开销
   操作系统、驱动等

总计：通常需要模型大小的 1.5-2 倍显存
```

### 具体例子

```
LLaMA-7B 的显存需求：

FP16 推理：
  模型权重：7B × 2字节 = 14GB
  KV Cache：约 2-4GB
  激活值：约 1-2GB
  总计：约 17-20GB

INT4 推理：
  模型权重：7B × 0.5字节 = 3.5GB
  KV Cache：约 2-4GB
  激活值：约 1-2GB
  总计：约 6.5-9.5GB
```

## 二、推理速度问题

### 推理速度的影响因素

```
影响推理速度的因素：

1. 模型大小
   参数越多，计算量越大
   
2. 序列长度
   序列越长，计算越慢
   
3. 硬件性能
   GPU 比 CPU 快很多
   
4. 批处理大小
   批处理可以提高吞吐量
```

### 推理速度对比

```
┌─────────────────────────────────────────────────────────────┐
│              LLaMA-7B 推理速度对比（A100 GPU）               │
├─────────────────────────────────────────────────────────────┤
│  精度        速度（tokens/s）    说明                       │
├─────────────────────────────────────────────────────────────┤
│  FP32        约 10              很慢                        │
│  FP16        约 30              正常                        │

│  INT4        约 80              很快                        │
└─────────────────────────────────────────────────────────────┘

用户期望：至少 20 tokens/s（实时对话）
```

### 成本计算

```
假设部署 LLaMA-7B 提供 API 服务：

使用 A100 80GB（FP16）：
  GPU 成本：$4/小时
  每天：$4 × 24 = $96
  每月：$96 × 30 = $2880

使用 RTX 3060（INT4）：
  GPU 成本：$0.2/小时
  每天：$0.2 × 24 = $4.8
  每月：$4.8 × 30 = $144

节省：$2880 - $144 = $2736/月（95%！）
```

## 四、优化的目标

```
┌─────────────────────────────────────────────────────────────┐
│                    模型优化的目标                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. 变小（减少模型大小）                                    │
│     - 量化：FP16 → INT4                                     │
│     - 剪枝：去掉不重要的参数                               │
│     - 蒸馏：用小模型学习大模型                             │
│                                                             │
│  2. 变快（提高推理速度）                                    │
│     - KV Cache：缓存计算结果                                │
│     - 批处理：一次处理多个请求                             │
│     - 并行计算：多 GPU 协同                                 │
│                                                             │
│  3. 变便宜（降低部署成本）                                  │
│     - 使用更便宜的硬件                                      │
│     - 提高资源利用率                                        │
│     - 减少显存需求                                          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 五、总结

### 为什么需要优化？

| 问题 | 原因 | 优化目标 |
|------|------|----------|
| 模型太大 | 参数量大 | 变小 |
| 推理太慢 | 计算量大 | 变快 |
| 成本太高 | 需要好硬件 | 变便宜 |

### 练习2：计算显存需求

计算 LLaMA-13B 在 FP16 和 INT4 下的显存需求。

---

## 练习答案

### 练习1答案

1. **为什么需要优化**：大模型需要大量显存和计算资源，成本高、速度慢。
2. **优化目标**：变小、变快、变便宜。
3. **常见方法**：量化、剪枝、蒸馏、KV Cache、批处理、并行计算。

### 练习2答案

```
LLaMA-13B（130亿参数）：

FP16：
  模型大小 = 13B × 2字节 = 26GB
  显存需求 ≈ 26GB × 1.5 = 39GB

INT4：
  模型大小 = 13B × 0.5字节 = 6.5GB
  显存需求 ≈ 6.5GB × 1.5 = 9.75GB
```
