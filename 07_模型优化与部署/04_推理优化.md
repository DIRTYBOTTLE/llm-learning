## 一、KV Cache（回顾）

### 什么是 KV Cache？

```
在第4章学过，KV Cache 可以加速生成：

原理：
  缓存之前位置的 K、V
  每次只计算新 token 的 K、V
  
效果：
  生成 100 个 token
  没有 KV Cache：计算 5050 次
  有 KV Cache：计算 100 次
```

### KV Cache 的显存占用

```
KV Cache 显存计算：

对于 LLaMA-7B：
  层数：32
  注意力头数：32
  每个头的维度：128
  序列长度：2048
  
  每层 KV Cache = 2 × seq_len × num_heads × head_dim
                = 2 × 2048 × 32 × 128
                = 16,777,216 个元素
  
  总 KV Cache = 32 层 × 16,777,216
             = 536,870,912 个元素
  
  FP16 下 = 536,870,912 × 2 字节 = 1GB

序列越长，KV Cache 越大！
```

## 二、批处理（Batching）

### 什么是批处理？

```
批处理 = 一次处理多个请求

单请求：
  请求1 → 模型 → 输出1
  请求2 → 模型 → 输出2
  请求3 → 模型 → 输出3
  
  需要调用模型 3 次

批处理：
  [请求1, 请求2, 请求3] → 模型 → [输出1, 输出2, 输出3]
  
  只需要调用模型 1 次
```

### 批处理的好处

```
┌─────────────────────────────────────────────────────────────┐
│                    批处理的好处                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. 提高吞吐量                                             │
│     - 一次处理多个请求                                     │
│     - 充分利用 GPU                                         │
│                                                             │
│  2. 减少延迟                                               │
│     - 减少模型调用次数                                     │
│     - 减少数据传输开销                                     │
│                                                             │
│  3. 降低成本                                               │
│     - 更高的 GPU 利用率                                     │
│     - 更少的硬件需求                                       │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 连续批处理（Continuous Batching）

```
传统批处理的问题：
  必须等所有请求都完成才能处理下一批
  如果某个请求很长，其他请求要等

连续批处理：
  请求可以随时加入或离开批次
  不需要等所有请求完成
  
  效果：
    - 更低的延迟
    - 更高的吞吐量
```

## 三、并行计算

### 数据并行

```
数据并行 = 多个 GPU 处理不同的数据

GPU1: 处理请求 1, 2, 3
GPU2: 处理请求 4, 5, 6
GPU3: 处理请求 7, 8, 9

特点：
  - 每个 GPU 都有完整的模型
  - 处理不同的数据
  - 适合高吞吐量场景
```

### 模型并行

```
模型并行 = 把模型切分到多个 GPU

GPU1: 模型的第 1-10 层
GPU2: 模型的第 11-20 层
GPU3: 模型的第 21-30 层

特点：
  - 每个 GPU 只有模型的一部分
  - 适合模型太大，单 GPU 放不下的情况
```

### 张量并行

```
张量并行 = 把单个层切分到多个 GPU

一个大的矩阵乘法：
  Y = X × W
  
  切分成：
  Y = X × [W1, W2] = [X × W1, X × W2]
  
  GPU1 计算 X × W1
  GPU2 计算 X × W2

特点：
  - 需要 GPU 之间高速通信
  - 适合单层很大的情况
```

## 四、使用 vLLM 加速推理

### 什么是 vLLM？

```
vLLM 是一个高性能推理框架

特点：
  - PagedAttention：更高效的 KV Cache 管理
  - 连续批处理：更高的吞吐量
  - 简单易用：API 兼容 OpenAI
```

### 安装 vLLM

```bash
pip install vllm
```

### 使用 vLLM 推理

```python
from vllm import LLM, SamplingParams

# 加载模型
llm = LLM(model="meta-llama/Llama-2-7b-hf")

# 设置采样参数
sampling_params = SamplingParams(
    temperature=0.7,
    top_p=0.9,
    max_tokens=100
)

# 生成
prompts = [
    "Hello, how are you?",
    "What is AI?",
    "Tell me a joke."
]

outputs = llm.generate(prompts, sampling_params)

for output in outputs:
    prompt = output.prompt
    generated = output.outputs[0].text
    print(f"Prompt: {prompt}")
    print(f"Generated: {generated}")
    print()
```

### vLLM 的性能

```
vLLM vs Transformers 推理速度对比：

LLaMA-7B（A100 GPU）：
  Transformers: 约 30 tokens/s
  vLLM: 约 100 tokens/s
  
  速度提升：约 3 倍！

原因：
  - PagedAttention 更高效
  - 连续批处理
  - 优化的 CUDA 内核
```

## 五、使用 llama.cpp 部署

### 什么是 llama.cpp？

```
llama.cpp 是一个 C++ 推理框架

特点：
  - 支持 CPU 推理（不需要 GPU！）
  - 支持多种量化格式（GGUF）
  - 轻量级，适合边缘设备
```

### 安装 llama.cpp

```bash
# 克隆仓库
git clone https://github.com/ggerganov/llama.cpp
cd llama.cpp

# 编译
make

# 下载 GGUF 模型
wget https://huggingface.co/TheBloke/Llama-2-7B-GGUF/resolve/main/llama-2-7b.Q4_0.gguf
```

### 使用 llama.cpp

```bash
# 运行推理
./main -m llama-2-7b.Q4_0.gguf -p "Hello" -n 100

# 启动 API 服务器
./server -m llama-2-7b.Q4_0.gguf --host 0.0.0.0 --port 8080
```

### llama.cpp 的性能

```
llama.cpp 在不同设备上的性能：

LLaMA-7B（Q4_0 量化）：
  M1 MacBook: 约 20 tokens/s
  RTX 3060: 约 40 tokens/s
  Intel i7 CPU: 约 5 tokens/s
  
适合：
  - 没有 GPU 的用户
  - 边缘设备部署
  - 私有化部署
```

## 七、总结

### 推理优化方法对比

| 方法 | 作用 | 适用场景 |
|------|------|----------|
| KV Cache | 加速生成 | 所有场景 |
| 批处理 | 提高吞吐量 | 高并发场景 |
| 并行计算 | 处理大模型 | 多 GPU 场景 |
| vLLM | 高性能推理 | 服务器部署 |
| llama.cpp | CPU 推理 | 边缘设备 |

### 选择建议

```
有 GPU，高并发：vLLM
有 GPU，低延迟：Transformers + KV Cache
没有 GPU：llama.cpp
边缘设备：llama.cpp + INT4 量化
```

### 练习1：理解 KV Cache

## 练习答案

### 练习1答案

1. **KV Cache**：缓存之前位置的 K、V，避免重复计算。
2. **为什么加速**：每次只计算新 token 的 K、V，不需要重新计算所有位置。

### 练习2答案

1. **高并发 API**：vLLM（支持连续批处理，吞吐量高）
2. **MacBook**：llama.cpp（支持 CPU 推理，针对 Apple Silicon 优化）
3. **无 GPU 服务器**：llama.cpp（支持 CPU 推理）
