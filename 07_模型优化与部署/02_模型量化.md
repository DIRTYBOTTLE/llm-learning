# 7.2 模型量化

> 量化是最常用的优化方法，把模型从"高清"变成"压缩"！

## 从你已经知道的开始

在上一节，你学了：
- 大模型需要大量显存

## 一、什么是量化？

### 简介

```
量化 = 把模型参数从高精度转换成低精度

例子：
  FP32（32位浮点）→ FP16（16位浮点）→ INT8（8位整数）→ INT4（4位整数）

类比：
  高清图片 → 压缩图片
  虽然质量略有下降，但文件小了很多！
```

### 量化的效果

```
┌─────────────────────────────────────────────────────────────┐
│                    量化的效果                                │
├─────────────────────────────────────────────────────────────┤
│  精度        每个参数占用    模型大小（7B）    效果          │
├─────────────────────────────────────────────────────────────┤
│  FP32        4 字节          28GB             最好           │
│  FP16        2 字节          14GB             很好           │
│  INT8        1 字节          7GB              好             │
│  INT4        0.5 字节        3.5GB            可接受         │
└─────────────────────────────────────────────────────────────┘
```

## 二、量化的数学原理

### 浮点数表示

```
FP32（32位浮点数）：
  符号位：1位
  指数位：8位
  尾数位：23位
  
  可以表示的范围：约 ±3.4 × 10^38
  精度：约 7 位有效数字

FP16（16位浮点数）：
  符号位：1位
  指数位：5位
  尾数位：10位
  
  可以表示的范围：约 ±6.5 × 10^4
  精度：约 3 位有效数字
```

### 整数表示

```
INT8（8位整数）：
  可以表示：-128 到 127（有符号）
  或者：0 到 255（无符号）

INT4（4位整数）：
  可以表示：-8 到 7（有符号）
  或者：0 到 15（无符号）
```

### 量化公式

```
量化过程：

原始值（FP16）：x
量化后的值（INT8）：x_q

量化公式：
  x_q = round(x / scale + zero_point)

反量化公式：
  x ≈ (x_q - zero_point) * scale

其中：
  scale = (max - min) / (2^n - 1)
  zero_point = round(-min / scale)
```

### 用具体数字理解

```
假设有一组权重值：
  [0.5, -0.3, 0.8, -0.1, 0.6]

量化成 INT8：

步骤1：找最大最小值
  min = -0.3
  max = 0.8

步骤2：计算 scale
  scale = (0.8 - (-0.3)) / (127 - (-128))
        = 1.1 / 255
        = 0.00431

步骤3：计算 zero_point
  zero_point = round(-(-0.3) / 0.00431)
             = round(69.6)
             = 70

步骤4：量化
  x_q[0] = round(0.5 / 0.00431 + 70) = round(186.1) = 186
  x_q[1] = round(-0.3 / 0.00431 + 70) = round(0.4) = 0
  x_q[2] = round(0.8 / 0.00431 + 70) = round(255.6) = 127（截断）
  x_q[3] = round(-0.1 / 0.00431 + 70) = round(46.8) = 47
  x_q[4] = round(0.6 / 0.00431 + 70) = round(209.3) = 209

量化后的值：[186, 0, 127, 47, 209]

步骤5：反量化验证
  x[0] ≈ (186 - 70) × 0.00431 = 0.49996 ≈ 0.5 ✓
  x[1] ≈ (0 - 70) × 0.00431 = -0.3017 ≈ -0.3 ✓
  x[2] ≈ (127 - 70) × 0.00431 = 0.24567 ≈ 0.8（误差较大）
```

## 三、常见的量化方法

### 1. 对称量化

```
对称量化：
  zero_point = 0
  scale = max(|min|, |max|) / (2^(n-1) - 1)

特点：
  - 简单
  - 适合权重（通常分布对称）
```

### 2. 非对称量化

```
非对称量化：
  scale = (max - min) / (2^n - 1)
  zero_point = round(-min / scale)

特点：
  - 更精确
  - 适合激活值（可能不对称）
```

### 3. 分组量化

```
分组量化：
  把权重分成多个组，每组有独立的 scale 和 zero_point

特点：
  - 更精确
  - 适合精度要求高的场景
```

## 四、常见的量化格式

### GPTQ

```
GPTQ = GPT Quantization

特点：
  - 专门为 GPT 模型设计
  - INT4 量化
  - 效果好，速度快
  - 需要校准数据

使用：
  from transformers import AutoModelForCausalLM
  
  model = AutoModelForCausalLM.from_pretrained(
      "TheBloke/Llama-2-7B-GPTQ",
      device_map="auto"
  )
```

### AWQ

```
AWQ = Activation-aware Weight Quantization

特点：
  - 考虑激活值的分布
  - INT4 量化
  - 效果比 GPTQ 更好
  - 速度也更快

使用：
  from transformers import AutoModelForCausalLM
  
  model = AutoModelForCausalLM.from_pretrained(
      "TheBloke/Llama-2-7B-AWQ",
      device_map="auto"
  )
```

### GGUF

```
GGUF = GPT-Generated Unified Format

特点：
  - 为 llama.cpp 设计
  - 支持 CPU 推理
  - 多种量化级别（Q4_0, Q5_0, Q8_0 等）
  - 适合边缘设备

使用：
  # 下载 GGUF 文件
  # 使用 llama.cpp 运行
  ./main -m llama-2-7b.Q4_0.gguf -p "Hello"
```

## 五、量化的代码实现

### 使用 Transformers 量化

```python
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig
import torch

# INT8 量化
bnb_config_8bit = BitsAndBytesConfig(
    load_in_8bit=True,
)

# INT4 量化
bnb_config_4bit = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.float16,
    bnb_4bit_use_double_quant=True,
)

# 加载量化模型
model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-2-7b-hf",
    quantization_config=bnb_config_4bit,
    device_map="auto",
)

tokenizer = AutoTokenizer.from_pretrained("meta-llama/Llama-2-7b-hf")

# 使用模型
input_ids = tokenizer("Hello", return_tensors="pt").to(model.device)
output = model.generate(**input_ids, max_length=50)
print(tokenizer.decode(output[0]))
```

### 查看量化信息

```python
# 查看模型参数
def print_model_size(model):
    """打印模型大小"""
    total_params = 0
    total_size = 0
    
    for name, param in model.named_parts():
        total_params += param.numel()
        total_size += param.numel() * param.element_size()
    
    print(f"总参数量: {total_params:,}")
    print(f"模型大小: {total_size / 1024**3:.2f} GB")

print_model_size(model)
```

## 六、量化的影响

### 精度损失

```
量化会带来一定的精度损失：

INT8 量化：
  - 精度损失很小（通常 < 1%）
  - 几乎不影响使用

INT4 量化：
  - 精度损失较大（可能 2-5%）
  - 对简单任务影响小
  - 对复杂任务可能有影响
```

### 速度提升

```
量化可以提升推理速度：

原因：
  1. 内存占用小，减少内存访问
  2. 整数计算比浮点快
  3. 可以使用专门的量化指令

效果：
  INT8：速度提升约 1.5-2 倍
  INT4：速度提升约 2-3 倍
```

## 七、总结

### 量化的关键点

| 概念 | 说明 |
|------|------|
| 量化 | 把高精度参数转换成低精度 |
| INT8 | 8位整数，精度损失小 |
| INT4 | 4位整数，精度损失较大 |
| GPTQ | 为 GPT 设计的量化方法 |
| AWQ | 考虑激活值的量化方法 |
| GGUF | 为 llama.cpp 设计的格式 |

### 选择建议

```
精度要求高：INT8 量化
显存有限：INT4 量化（GPTQ 或 AWQ）
边缘设备：GGUF 格式
```

## 练习答案

### 练习1答案

1. **量化**：把模型参数从高精度转换成低精度（比如 FP16 → INT4）。
2. **为什么变小**：每个参数占用的字节数减少（FP16=2字节，INT4=0.5字节）。
3. **缺点**：会带来一定的精度损失。

### 练习2答案

```
LLaMA-7B（70亿参数）：

FP16：7B × 2字节 = 14GB
INT8：7B × 1字节 = 7GB
INT4：7B × 0.5字节 = 3.5GB
```
