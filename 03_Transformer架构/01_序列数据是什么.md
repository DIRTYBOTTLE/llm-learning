# 3.1 序列数据是什么

> 从"一张图片"到"一段文字"，数据不再是一坨数字，而是一串有顺序的数字。

## 从你已经知道的开始

在第2章，你学了 CNN（卷积神经网络）。CNN 擅长处理**图片**。

为什么 CNN 能处理图片？
- 图片是一张二维的网格（像素矩阵）
- CNN 用"滑动窗口"在图片上滑动，提取局部特征
- 比如：边缘、纹理、形状

**但是，文字和图片不一样。**

## 什么是序列数据

**序列数据**：数据的顺序很重要，改变顺序会改变意思。

### 举个例子

| 数据类型 | 示例 | 顺序重要吗？ |
|---------|------|-------------|
| 图片 | 一张猫的照片 | 不太重要（像素打乱一点还是猫） |
| 文字 | "我爱学习" | 非常重要（"学习爱我"意思完全不同） |
| 股票价格 | [100, 102, 105, 103] | 非常重要（这是时间序列） |
| 语音 | 一段录音 | 非常重要（按时间顺序的声波） |

### 生活中的序列数据

```
文字：  "今天天气真好"  →  顺序：今天 → 天气 → 真好
股票：  周一100元 → 周二102元 → 周三105元  →  顺序：时间先后
语音：  声波按时间顺序排列  →  顺序：时间先后
```

## 为什么 CNN 处理不好序列数据

### 问题1：CNN 不懂"顺序"

CNN 把数据当成一个"无序的集合"来看待。

```
对于 CNN 来说：
"我爱学习"  和  "学习爱我"  可能差不多

但实际上：
"我爱学习"  →  正常句子
"学习爱我"  →  意思完全不同！
```

### 问题2：CNN 看不远

CNN 的卷积核很小（比如 3×3），只能看到"局部"的信息。

```
句子："我昨天去了北京，那里很冷，所以我买了羽绒服"

CNN 只能看到局部：
[我 昨天 去了]  →  只能看到相邻的几个词

但"北京"和"很冷"相隔很远，CNN 很难把它们联系起来
```

### 问题3：CNN 不能处理变长的序列

图片的大小是固定的（比如 28×28），但文字的长度是变化的。

```
句子1："好"        →  1个字
句子2："今天天气好"  →  5个字
句子3："今天天气真好，适合出去玩"  →  10个字

CNN 需要固定大小的输入，怎么处理这些不同长度的句子？
```

## 我们需要什么样的新模型

一个能处理序列数据的模型，需要满足：

1. **能感知顺序**：知道"我爱学习"和"学习爱我"不一样
2. **能看远**：能捕捉长距离的依赖关系
3. **能处理变长**：能处理不同长度的序列

**答案：循环神经网络（RNN）**

下一节我们来学习 RNN 是怎么工作的。

## 练习题

### 练习1：判断序列数据

以下哪些是序列数据？为什么？

1. 一段文字："Hello World"
2. 一张图片：猫的照片
3. 过去7天的气温：[20, 22, 25, 23, 21, 19, 18]
4. 一个人的脸部特征：[眼睛位置, 鼻子位置, 嘴巴位置]

### 练习2：CNN 的局限性

请用你自己的话解释，为什么 CNN 处理不好文字数据？

### 练习3：思考

如果让你设计一个能处理文字的模型，你会怎么设计？

---

## 答案

### 练习1答案

1. **是序列数据**：词的顺序很重要
2. **不是序列数据**：像素的顺序不太重要
3. **是序列数据**：时间顺序很重要
4. **不是序列数据**：脸部特征的位置关系是固定的

### 练习2答案

CNN 处理不好文字的原因：
1. CNN 不懂顺序，"我爱学习"和"学习爱我"对它来说差不多
2. CNN 看不远，只能看到局部的几个词
3. CNN 需要固定大小的输入，但文字长度是变化的

### 练习3答案

（开放性问题，没有标准答案）

一些可能的设计思路：
- 用一个"记忆"来记住之前看到的信息
- 让模型能关注到序列中任意两个位置的关系
- 用某种方式告诉模型每个词的位置
